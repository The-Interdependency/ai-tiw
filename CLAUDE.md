## What This Repo Is

**ai-tiw** (AI — The Interdependent Way) is an **archive repository** containing unedited responses from major AI models when presented with the concepts and source material of [the interdependent way](https://interdependentway.org) — a theory of consciousness and architecture grounded in triadic coherence, coherence primes, and recursive self-modelling.

This is a **content archive**, not a software project. There is no code, no test suite, and no CI pipeline.

## Content Organization

Each model folder contains one or more `.md` files named descriptively (e.g., `grok-tiw.md`, `full-canon.md`, `01-response-to-the-interdependent-way.md`). Content is unedited AI output, preserving each model's reasoning and synthesis exactly as produced.

The `files/` directory contains AI-generated artifacts (code, diagrams, documents) prompted from the source material.

---

## Conventions

- **Do not edit response content.** Files represent unaltered AI output. Factual corrections or editorial commentary must be added in a clearly marked separate section.
- **File naming:** `<descriptive-slug>.md` within each model's folder.
- **Accreditation line:** Each model folder's `README.md` and most individual
  response files open with an `Accreditation:` line naming the model, e.g.
  `Accreditation: Claude generated; context, prompt Erin Spencer.` (the model
  name is substituted per folder: GPT, Gemini, Mistral, DeepSeek, Meta AI, …).
  The repo-level `README.md` uses the generic tagline
  *"AI generated; context, prompt Erin Spencer"*. Apply the per-model
  `Accreditation:` line to new content; a few legacy response files (e.g.
  `grok/grok-tiw.md`) predate it and lack one.
- **License:** **MIT** — the full verbatim MIT License text is in `LICENSE`.
  Copyright (c) 2026 Erin Patrick Spencer.

## Adding New Responses

1. Create or navigate to the appropriate `<model>/` folder.
2. Add a `.md` file with a descriptive name.
3. Update the relevant table in `README.md` with the file name and a one-line description.

## Adding a New Model Folder

1. Create `<model-name>/` directory.
2. Add at least one response `.md` file.
3. Add the model to the table in `README.md`.

## Agent module-build doctrine

Before adding a new module, route, service, adapter, schema, worker, engine,
UI panel, migration, or experiment, read:

`./.agents/skills/meta-module-build/SKILL.md`

New module work should start with a `MODULE_BUILD` block. Unknown fields must
be marked `hmmm`, not guessed.

This is an archive/content repo: `MODULE_BUILD` is required only for new
executable or tooling modules, not for archived model-response files or other
historical content.
